# Phase 3: Git pull-through Implementation Plan

> REQUIRED SUB-SKILL: superpowers:executing-plans (inline, TDD per task).

**Goal:** Clients clone public upstream repos from the LAN mirror over dumb HTTP; repos are seeded/updated and (on-miss) auto-cloned.

**Spec:** `docs/superpowers/specs/2026-11-05-phase3-git-design.md`

## Global Constraints
- Dumb-HTTP only (bare `--mirror` + `update-server-info`, plain nginx static). No fcgiwrap.
- Host/path validated to a strict charset before any `git` call. Upstream is always `https://<host>/<path>`.
- `git` binary required only for the git feature. Keep the managed-marker / `--upgrade` contract.

## Review Focus
- An attacker-influenced repo path must never reach `git` as a flag or shell (`../`, `;`, `$(`, leading `-`, `--upload-pack`) — Task 1 validation, used everywhere.
- A clone interrupted mid-fetch must not be served as complete — Task 2 (clone to a temp dir, rename into place only on success).
- Store dir maps 1:1 to the client URL (no `.git` suffix mismatch) — Task 1.

- [ ] Test: create a source repo with a commit; `_git_ensure_mirror` with an upstream override (`file://` or local path) clones `--mirror` into the store dir, runs `update-server-info`, and a `git clone` of the store dir has the commit. `_git_update_mirror` after a new upstream commit brings it across.
